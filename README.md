# Проверка SearchInform КИБ на синтетических данных

Дата подготовки: 16.11.2026. Все значения вымышлены, никаких реальных персональных данных, учетных данных и секретов нет. Точные возможности зависят от версии, ОС, лицензии, агентов, каналов и настроек конкретной инсталляции. Ни один файл сам по себе не гарантирует срабатывание штатной политики.

## Подготовка

1. Согласуйте с администратором тестовую учетную запись, контролируемый компьютер, разрешенные USB и тестовые адреса/ресурсы. Фиксируйте версию КИБ, ОС, агент, работающие модули и состояние связи с сервером.
2. Настройте отдельное правило точного поиска содержимого по строке `DLPTEST-7Q4M-83PX` для тестовых пользователя, компьютера и нужного канала. Сначала включите регистрацию/уведомление, затем отдельно действие блокировки, если оно доступно и требуется. Уточните, что правило охватывает вложения и конкретный формат. Включите журналирование и дождитесь применения правила.
3. Файл `00_control.txt` не содержит маркер; остальные образцы содержат его в извлекаемом тексте. Проверьте контроль и положительный образец одинаковым действием. Без специального правила стандартные политики могут их не распознать; контроль может блокироваться из-за иной политики.
4. После каждого действия проверьте и запись у получателя/на носителе, и консоль: событие, пользователь, время, канал, файл, результат, правило, действие и наличие теневой копии. Регистрация, уведомление и блокировка — разные результаты. Подождите задержку обработки, согласованную с администратором. Не повторяйте действие до записи результата.
5. Используйте только свои тестовые ресурсы и согласованные каналы. Не отправляйте образцы в посторонние сервисы. Если доступ запрещен целиком, сначала зафиксируйте это и попросите администратора отдельно разрешить канал для теста контента.

## Состав

| Файл | Проверка |
|---|---|
| 00_control.txt | Отрицательный контроль: нет маркера и похожих на конфиденциальные данных. |
| 01_sample.txt | Текст UTF-8; положительный контроль. |
| 02_sample.csv | Таблица UTF-8 с BOM, разделитель запятая; положительный контроль. |
| 03_sample.docx | Текст и таблица Word. |
| 04_sample.xlsx | Маркер в обычной видимой ячейке B2. |
| 05_sample.pdf | PDF с текстовым слоем, не скан и не OCR. |
| 06_plain.zip | Незашифрованный ZIP с 01_sample.txt внутри. |
| 07_nested.zip | Незашифрованный ZIP → inner.zip → 01_sample.txt; одна вложенность. |

Текстовый маркер проверяет настроенное буквальное правило, а не автоматическое распознавание ПДн, банковских данных или паролей. Для оценки таких встроенных детекторов нужны отдельно согласованные заведомо синтетические наборы и критерии; здесь они не проверяются. Нет проверки OCR, шифрованных архивов, изображений, сканов, больших файлов и всех форматов.

## Матрица тест-кейсов

В столбце «Ожидание» описан критерий для специально настроенной политики блокировки, а не гарантированное поведение по умолчанию. Для режима мониторинга замените «отказ» на «операция разрешена + событие» по согласованной политике. При каждом тесте запишите фактическое значение в журнал ниже.

| ID | Действие / канал | Файл | Ожидание при тестовом правиле |
|---|---|---|---|
| USB-0 | Копирование на согласованную флешку | 00_control.txt | Копирование успешно; правило маркера не сработало. |
| USB-1 | Копирование на ту же флешку | 01_sample.txt | Отказ записи и событие по маркеру; проверить фактическое отсутствие полного файла. |
| USB-2 | То же | 02_sample.csv, 03_sample.docx, 04_sample.xlsx, 05_sample.pdf по отдельности | Для каждого: отказ и событие, если поддерживается разбор формата. |
| USB-3 | То же | 06_plain.zip | Отказ и событие, если политика анализирует содержимое ZIP. |
| USB-4 | То же | 07_nested.zip | Отказ и событие при поддержке и включенной достаточной глубине вложенности; отдельно зафиксировать ограничение. |
| WEB-0/1 | Загрузить на согласованный HTTPS веб-ресурс через браузер | 00_control.txt, затем 01_sample.txt | Контроль проходит; маркер блокируется и регистрируется при включенном правиле. |
| MAIL-0/1 | Отправить на согласованный тестовый адрес | 00_control.txt, затем 03_sample.docx | Контроль доставлен; тестовое вложение не доставлено и событие зарегистрировано. Проверить исходящие и ящик получателя. |
| CLOUD-0/1 | Загрузить в согласованное облако | 00_control.txt, затем 04_sample.xlsx | Контроль загружен; тестовый файл не появился у получателя, событие зарегистрировано. Отдельно проверить браузер и клиент, если используются. |
| IM-0/1 | Отправить в согласованный тестовый чат | 00_control.txt, затем 05_sample.pdf | Контроль получен; файл с маркером не получен и зарегистрирован. Указать приложение и версию. |
| PRINT-0/1 | Отправить на согласованный тестовый принтер | 00_control.txt, затем 03_sample.docx | Контроль распечатан; положительный образец не напечатан, событие зарегистрировано. |
| CLIP-0/1 | Скопировать в согласованное приложение нейтральный текст, затем строку маркера из TXT | 00_control.txt, 01_sample.txt | Контроль вставлен; маркер не вставлен и зарегистрирован при настроенном правиле буфера. |
| FTP-0/1 | При наличии согласованного FTP/FTPS стенда отправить файлы | 00_control.txt, затем 01_sample.txt | Контроль доставлен; маркер блокируется и регистрируется, если эта установка поддерживает такую блокировку. |

Повторите форматы и архивы в нужных сетевых каналах: поддержка извлечения и блокировки может различаться. Для ZIP особенно важно проверять отдельно факт передачи, событие, обнаружение маркера и результат блокировки; успешная передача не доказывает отсутствие контроля, а блокировка архива целиком не доказывает извлечение содержимого.

## Журнал результатов

Для каждой отдельной операции заполните строку: ID; дата и время с часовым поясом; пользователь/ПК/ОС; версия КИБ и агент; канал/приложение; файл; ID и режим политики; действие пользователя; результат у отправителя; что реально оказалось у получателя/на USB; событие и его ID; найден ли именно маркер; уведомление; блокировка; теневая копия; задержка; примечание. Значения: «да», «нет», «не проверено», «не применимо». Не смешивайте отсутствие события с отсутствием блокировки.

Пример пустой строки: `USB-1 | ... | ... | 01_sample.txt | ... | ... | ... | ... | ... | ... | ... | ... | ... | ...`
