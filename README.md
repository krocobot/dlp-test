# Проверка SearchInform КИБ на синтетических данных

Дата подготовки: 16.11.2026. Все значения вымышлены. Точные возможности зависят от версии, ОС, лицензии, агентов, каналов и настроек инсталляции. Ни один файл сам по себе не гарантирует срабатывание политики.

## Подготовка

1. Согласуйте с администратором тестовую учетную запись, контролируемый компьютер, разрешенные USB и тестовые адреса/ресурсы. Фиксируйте версию КИБ, ОС, агент, работающие модули и состояние связи с сервером.
2. Настройте отдельное правило точного поиска по строке `DLPTEST-7Q4M-83PX` для тестовых пользователя, компьютера и нужного канала. Сначала регистрацию/уведомление, затем при необходимости блокировку. Уточните разбор вложений и форматов, включите журналирование и дождитесь применения политики.
3. `00_control.txt` не содержит маркер; положительные образцы содержат его. Проверяйте одинаковым действием отрицательный и положительный контроль.
4. После каждого действия проверьте и результат доставки/записи, и событие в консоли: пользователя, время, канал, файл, правило, действие, результат и наличие теневой копии. Регистрация, уведомление и блокировка — разные результаты.
5. Используйте только согласованные тестовые ресурсы.

## Состав исходного набора

| Файл | Проверка |
|---|---|
| 00_control.txt | Отрицательный контроль |
| 01_sample.txt | Текст UTF-8 |
| 02_sample.csv | Таблица UTF-8 с BOM |
| 03_sample.docx | Текст и таблица Word |

**Статус публикации:** данный репозиторий пока содержит только текстовые файлы и README. DOCX, XLSX, PDF и внутренние ZIP из исходного архива не были перенесены. Для полного набора используйте исходный `DLP_test_bundle.zip`; он доступен в чате, где предоставлен. Этот README адаптирован для публичной версии.

## Матрица тест-кейсов

| ID | Действие | Файл | Критерий при специально настроенном правиле блокировки |
|---|---|---|---|
| USB-0 | Копирование на разрешённую флешку | 00_control.txt | Успех, отсутствие события по маркеру |
| USB-1 | То же | 01_sample.txt | Отказ и событие по маркеру |
| USB-2 | То же | CSV, DOCX, XLSX, PDF по отдельности | Отказ и событие при поддержке формата |
| USB-3 | То же | 06_plain.zip | Отказ и событие при анализе ZIP |
| USB-4 | То же | 07_nested.zip | Отказ и событие при достаточной глубине вложенности |
| WEB-0/1 | Загрузка на согласованный HTTPS-ресурс | Контроль и TXT | Контроль проходит, маркер блокируется |
| MAIL-0/1 | Отправка тестового письма | Контроль и DOCX | Контроль доставлен, тестовое вложение нет |
| CLOUD-0/1 | Загрузка в согласованное облако | Контроль и XLSX | Проверить браузер и клиент |
| IM-0/1 | Отправка в тестовый чат | Контроль и PDF | Контроль проходит, маркер блокируется |
| PRINT-0/1 | Тестовый принтер | Контроль и DOCX | Контроль печатается, маркер блокируется |
| CLIP-0/1 | Буфер обмена | Контроль и TXT | Контроль вставляется, маркер блокируется |
| FTP-0/1 | Согласованный FTP/FTPS | Контроль и TXT | Проверить доставку и событие |

В режиме мониторинга ожидается разрешенная операция + событие. Фактическую поддержку канала и формата нужно проверять отдельно. Контроль может блокироваться другой политикой.

## Журнал результатов

Для каждой операции запишите: ID, дату и часовой пояс, пользователя, ПК, ОС, версию КИБ и агента, канал и приложение, файл, правило, действие пользователя, результат у отправителя, фактическое содержимое у получателя, событие и его ID, найденный маркер, уведомление, блокировку, теневую копию, задержку и примечания.
